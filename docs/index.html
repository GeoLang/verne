🧳 Verne

Verne moves your data out of a file or a hosted ArcGIS service and into GeoLang. Every item gets a verdict before anything moves: carried faithfully, approximated, or not carried.

How It Works

1. Inspect

  • verne inspect reads the source
  • Prints a report with one verdict per item
  • JSON output on request

2. Extract

  • verne extract writes everything to a folder: datasets, features, attachments
  • A GeoPackage beside it when the source is a geodatabase

3. Load

  • verne load creates it all in a running ptolemy
  • The source is never written to, at any step

Not a One-Time Migration

🔁 Delta runs

  • After the first load, each run carries only what changed since the last
  • Inserts, updates, deletes and attachment changes all flow across
  • Feature ids stay stable, so a feature's history stays one feature

⏰ On your schedule

  • No daemon: run it from cron or a timer
  • Each run picks up where the last ended
  • demo/migration-loop.sh runs the full loop against a live service

The Fidelity Report

✅ Faithful

  • Carried across without loss
  • Names the GeoLang component it goes to

⚠️ Approximated

  • Carried with something left behind
  • The row must say what — a loss list cannot be empty

🚫 Unsupported

  • No home in GeoLang
  • With the reason

➖ Not applicable

  • The source cannot have the thing at all
  • Nothing carried, nothing lost

An inventory that cannot be produced is an error, never an empty list, so a source verne failed to read is not mistaken for a clean one.

Sources

🗂️ KML / KMZ

  • Reads no network, takes no credentials
  • A remote link or overlay is reported, never fetched

🗄️ Esri File Geodatabase

  • Feature classes, fields, aliases, domains, subtypes, relationship classes, attachments
  • Anything that cannot be carried is named in the report, never silently dropped
  • Extraction also writes a GeoPackage

🌐 Hosted ArcGIS Feature Services

  • REST reads only, by FeatureServer root
  • Token from VERNE_ARCGIS_TOKEN, or minted from a client id and secret — never an argument
  • verne services lists a portal's feature services

What Migrates from ArcGIS

For a hosted feature or map service, read over the documented REST API:

✅ Carried

  • Layers and tables: fields, aliases, domain bindings
  • Coded and range domains
  • Subtypes with defaults and per-subtype domain assignments
  • Relationships, as both ends describe them
  • Attachments — every blob lands on its feature
  • All features, paged, with the original coordinates preserved beside the reprojected ones
  • Layer symbology, stored verbatim as Esri drawing info
  • Time awareness and metadata records
  • Private services (token or OAuth client credentials)
  • Enterprise versioned data, one named version at a time
  • Ongoing edits: inserts, updates, deletes and attachment changes flow across on every delta run

🚫 Left behind — named in the report, never dropped silently

  • Rasters: named for the platform's raster tooling, never fetched
  • The version tree: one named version is read at a time
  • Group-layer hierarchy: members flatten to datasets, the grouping becomes a report row
  • Relationship labels and rules: not visible over REST, created empty
  • Symbology and aliases are stored, not yet rendered by any platform screen
  • Binary column values (attachment bytes are the exception)
  • Web maps, dashboards, and other portal content: out of scope, verne reads FeatureServer and MapServer only

A file geodatabase adds feature datasets, annotation and dimension classes, and attachment tables. Topologies, networks, parcel fabrics, mosaic datasets and attribute rules are named in the report and not carried.

Quick Start

# print a markdown report
verne inspect sites.kml

# a hosted feature service
verne inspect https://host/arcgis/rest/services/Wells/FeatureServer

# write the features and the semantics out
verne extract wells.gdb --out ./wells-extract --operator you@example.com

# create them in a running ptolemy
export VERNE_PTOLEMY_TOKEN=<a bearer token that may write>
verne load ./wells-extract --ptolemy http://localhost:3000
