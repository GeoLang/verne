🧳 Verne

Read-only inventory of a third-party geospatial source. Verne opens a file or a hosted service, lists the contents, and reports for each item whether GeoLang can carry it faithfully, only approximate it, or not hold it at all — then extracts and loads it.

How It Works

verne inspect reads a source and prints a markdown report (JSON beside it on request) with one verdict per item. verne extract writes the source out as a sidecar ptolemy can load — datasets and their semantics, the features, and the attachments on them — with a GeoPackage beside it when the source is a geodatabase. verne load creates what the sidecar describes in a running ptolemy. The source is never written to, in any of the three.

Not a One-Time Migration

Verne can keep running against the third-party service after the first load. A delta extraction fetches what changed since the previous run — from the service's own change tracking when it has one, or verne's own diff of the full state when it does not — and carries the inserts, updates and deletes into ptolemy. An update keeps the feature id the first extraction minted, so a feature's history in ptolemy stays one feature across every window, and attachments are diffed the same way. Each delta is the basis for the next, so a migration window is a chain of cheap deltas. demo/migration-loop.sh runs the whole loop against a live service: full extract, load, delta, delta load, then verifies the migrated counts.

The Fidelity Report

✅ Faithful

  • Carried across without loss
  • Names the GeoLang component it goes to

⚠️ Approximated

  • Carried with something left behind
  • The row must say what — a loss list cannot be empty

🚫 Unsupported

  • No home in GeoLang
  • With the reason

➖ Not applicable

  • The source cannot have the thing at all
  • Nothing carried, nothing lost

An inventory that cannot be produced is an error, never an empty list, so a source verne failed to read is not mistaken for a clean one.

Sources

🗂️ KML / KMZ

  • Pure Rust, no GDAL
  • Reads no network, takes no credentials
  • A NetworkLink or remote overlay is reported as outside the inventory, never fetched

🗄️ Esri File Geodatabase

  • Behind the gdb build feature, GDAL 3.8+ via OpenFileGDB — Esri's SDK is never loaded
  • Feature classes, fields, aliases, domains, subtypes, relationship classes, attachments
  • What GDAL cannot model is named from the catalogue rather than silently dropped
  • Extraction also writes a GeoPackage

🌐 Hosted ArcGIS Feature Services

  • REST reads only, by FeatureServer root
  • Token from VERNE_ARCGIS_TOKEN, or minted from a client id and secret — never an argument
  • verne services lists a portal's feature services

Quick Start

# print a markdown report
verne inspect sites.kml

# a hosted feature service
verne inspect https://host/arcgis/rest/services/Wells/FeatureServer

# write the features and the semantics out
verne extract wells.gdb --out ./wells-extract --operator you@example.com

# create them in a running ptolemy
export VERNE_PTOLEMY_TOKEN=<a bearer token that may write>
verne load ./wells-extract --ptolemy http://localhost:3000

Architecture

verne/
├── crates/
│   ├── verne-core/     # inventory model, verdicts, report rendering
│   ├── verne-kml/      # KML/KMZ reader (pure Rust)
│   ├── verne-gdb/      # file geodatabase adapter (GDAL 3.8+, `gdb` feature)
│   ├── verne-arcgis/   # hosted feature service reader (REST)
│   ├── verne-load/     # sidecar loader targeting ptolemy
│   └── verne-cli/      # inspect, extract, services, load
└── docs/               # This page
